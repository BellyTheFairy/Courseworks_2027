TripPlanner

Платформа для совместного планирования путешествий (TripPlanner) — это полноценное многопользовательское веб-приложение, которое решает проблему хаоса в групповых чатах при организации поездок. Проект отлично подходит для курсовой работы, так как включает работу с реляционной базой данных, сложную бизнес-логику, внешние API и интерактивный интерфейс.
Основной функционал (MVP)
Чтобы не закопаться в деталях и успеть к защите, стоит сфокусироваться на 4 ключевых модулях:
•	Управление поездками и участниками. Создание события, генерация пригласительной ссылки и распределение ролей (организатор и обычные участники).
•	Голосование за даты и места. Возможность предложить несколько вариантов дат или городов, поставить лайки и автоматически определить вариант-победитель.
•	Интерактивная карта маршрута. Добавление точек интереса (отели, музеи, кафе) с привязкой к дням поездки и отображением маркеров на карте.
•	Сплит-трекер бюджета (аналог Splitwise). Учет общих трат с автоматическим расчетом, кто кому и сколько должен вернуть по итогам поездки.

Детальное распределение ролей для 3 человек
Участник 1: Архитектор БД и бизнес-логики (Backend Core)
Отвечает за фундамент приложения и сложные алгоритмы расчетов.
•	Проектирование схемы БД. Создание таблиц пользователей, поездок, точек маршрута, голосов и транзакций (PostgreSQL или SQLite на старте).
•	Алгоритм взаиморасчетов. Написание логики на Python, которая минимизирует количество переводов между участниками при закрытии общего бюджета.
•	Агрегация данных. Подсчет результатов голосований, проверка прав доступа (например, удалять поездку может только создатель) и генерация итогового чек-листа или PDF-отчета.
Участник 2: Разработчик API и интеграций (Backend API)
Связывает базу данных с внешним миром и клиентской частью.
•	Система авторизации. Регистрация, вход, хеширование паролей и выдача JWT-токенов (или сессий) для безопасного доступа.
•	REST API эндпоинты. Реализация CRUD-операций (создание, чтение, обновление, удаление) для всех сущностей с помощью FastAPI или Django REST Framework.
•	Документация и валидация. Настройка автоматической документации Swagger (OpenAPI) и строгая проверка входящих данных через Pydantic или сериализаторы Django.
Участник 3: Frontend-разработчик и интегратор карт
Отвечает за визуальную часть, удобство использования и работу с картографическими сервисами.
•	Верстка интерфейса. Создание адаптивных страниц (список поездок, дашборд конкретной поездки, вкладка бюджета) на HTML/CSS/JS (или с использованием React/Vue, либо шаблонизатора Jinja2 + HTMX).
•	Интеграция карт. Подключение бесплатных библиотек (например, Leaflet.js + карты OpenStreetMap или API Яндекс.Карт) для установки меток по клику и построения маршрутов.
•	Связь с API. Отправка асинхронных запросов (Fetch API / Axios) к бэкенду для обновления голосов и расходов без перезагрузки страницы.
